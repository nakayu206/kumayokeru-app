# テスト方針

TekuShareと同様、単体テストと結合テストを分けて管理する。

## 基本方針

- **単体テスト**: 1件ずつの責務でテスト。Widgetの表示・操作・状態変化を個別に検証
- **結合テスト**: ユーザー操作の流れをまとめてテスト。画面遷移など複数要素をまたぐシナリオ

## ディレクトリ構成

```
test/                    # 単体テスト
└── presentation/pages/ / widgets/

integration_test/        # 結合テスト
└── app_test.dart
```

## 実行コマンド

```bash
flutter test                          # 単体テスト全件
flutter test --reporter expanded      # 詳細ログあり
flutter test integration_test/        # 結合テスト(実機/エミュレータ必要)
```

## テスト作成の指針

- テストファイルは`test/`以下に対象と同じディレクトリ構成で配置
- `group`でページ・Widget名をまとめ、`testWidgets`で1つの振る舞いをテスト
- 画面サイズは`tester.view.physicalSize`でスマートフォンサイズ(1170×2532)に統一
- PRと同じタイミングでテストを必ず作成する([コード規約.md](コード規約.md)参照)

## 対象別テスト内容

| テスト種別 | 内容 | ツール |
|---|---|---|
| ユニットテスト | ビジネスロジック(音声再生間隔計算、オフライン同期ロジック等) | `flutter_test`, `mockito` |
| ウィジェットテスト | 画面単位のUI動作確認 | `flutter_test` |
| 結合テスト | 実機での動作確認(バックグラウンド再生、GPS取得、オフライン地図) | `integration_test` |
| 実機フィールドテスト | 実際の登山道での圏外動作・バッテリー消費・音量到達距離の検証 | 手動テスト(Phase 0, Phase 2で実施) |
| 負荷・同期テスト | 複数ユーザーの位置共有・投稿が同時に発生した場合の同期整合性(AWS DynamoDB) | バックエンドの結合テスト |

## CI(`.github/workflows/ci.yml`)での実行方針

- PR作成・mainへのpush時に、フォーマット/静的解析/テストを自動実行
- 単体テストはLinuxデスクトップターゲット(`-d linux`)で実行する。`isar_flutter_libs`はFFIプラグインのため、
  ヘッドレスの`flutter test`ではネイティブライブラリが初期化されず、`-d linux`が必須
- 結合テスト(`integration_test/`)は実機/エミュレータが必要なため、現状CIから除外
- Isar/AWS(Amplify)依存のテストファイルが増えてきたら、TekuShareと同様にLinux非対応の
  テストファイルを明示的に除外する運用に切り替える想定

## 実機動作確認の記録方法

バックグラウンド音声・位置情報などOS依存処理を含むPRは、実機/エミュレータでのスクリーンショットや
動作確認結果をPR本文に添付する(`.github/pull_request_template.md`のチェックリスト参照)。
