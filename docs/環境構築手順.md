# クマヨケール 環境構築手順

> 新しいPC・新メンバー参加時の初期セットアップ手順。上から順に実行すれば動かせる状態になる。

---

## 0. 前提

| 項目 | バージョン |
|---|---|
| OS | Windows 10/11 または macOS |
| Flutter | 3.41.x以上 |
| Dart | 3.11.x以上(Flutter同梱) |
| Android Studio | 最新安定版 |
| Xcode | 最新安定版(macOSのみ) |
| VS Code | 最新版(推奨エディタ) |

---

## 1. Flutter SDKのインストール

### Windows

1. [Flutter SDK](https://docs.flutter.dev/get-started/install/windows) をダウンロード
2. `C:\src\flutter` などに展開(パスにスペース・日本語は禁止)
3. 環境変数`Path`に`C:\src\flutter\bin`を追加
4. 確認: `flutter --version`

### macOS

```bash
brew install --cask flutter
flutter --version
```

---

## 2. Android開発環境

### 2-1. Android Studioをインストール

[Android Studio公式](https://developer.android.com/studio) からインストーラーを取得して実行。初回起動時のセットアップウィザードでAndroid SDK / SDK Platform / Android Virtual Deviceを入れる。

### 2-2. ライセンス同意

```powershell
# Windows
$env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"
flutter doctor --android-licenses
```

すべて`y`で同意する。

### 2-3. エミュレータ作成(AVD)

#### コマンドラインで作成する場合(Windows)

```powershell
$env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"

# システムイメージのインストール(Android 14 / Google Play / x86_64)
'y' | & "$env:LOCALAPPDATA\Android\Sdk\cmdline-tools\latest\bin\sdkmanager.bat" `
  "system-images;android-34;google_apis_playstore;x86_64"

# AVD作成(pixel_6ベース)
echo "no" | & "$env:LOCALAPPDATA\Android\Sdk\cmdline-tools\latest\bin\avdmanager.bat" `
  create avd -n kumayokeru_pixel `
  -k "system-images;android-34;google_apis_playstore;x86_64" `
  -d pixel_6
```

#### Android Studioで作成する場合

`More Actions` → `Virtual Device Manager` → `Create Device` でPixel 6 / API 34を選択。

## 3. iOS開発環境(macOSのみ)

```bash
sudo xcode-select -s /Applications/Xcode.app
sudo xcodebuild -license

brew install cocoapods
pod setup
```

> `sudo gem install cocoapods` は使わないこと。macOS標準のRubyは古く、CocoaPodsが依存する`ffi`がRuby 3.0以上を要求するためインストールに失敗する。必ずHomebrew経由でインストールする。

> Windowsユーザーは iOS ビルドをスキップしてOK(Macで別途実施)。

iOSのFlavor(dev/stg/prod)関連のBuild Configuration/Schemeは、Xcode上での作成が未着手(Windows環境で作業しているため)。
`ios/Flutter/*.xcconfig`は作成済みだが、`--flavor`オプションでエラーが出る場合は
[`ios/FLAVOR_SETUP.md`](../ios/FLAVOR_SETUP.md) の手順に従ってMacで設定すること。

```json
    "editor.tabCompletion": "onlySnippets"
  }
}
```

## 7. 環境(Flavor)の使い分け

| Flavor | applicationId | アプリ名 | 用途 |
|---|---|---|---|
| dev | `com.kumayokeru.app.dev` | クマヨケール(dev) | 開発・検証 |
| stg | `com.kumayokeru.app.stg` | クマヨケール(stg) | テスト・QA |
| prod | `com.kumayokeru.app` | クマヨケール | リリース |

3環境とも別applicationIdなので**同じ端末に並行インストール可能**。

## 8. リリースAPK / IPAのビルド

### Android


## 9. トラブルシューティング

### `JAVA_HOME`が設定されていない

```powershell
$env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"
```

### エミュレータが起動しない(lockファイル残存)

```powershell
Get-Process emulator,qemu-system-* -ErrorAction SilentlyContinue | Stop-Process -Force
Remove-Item -Recurse -Force "$env:USERPROFILE\.android\avd\kumayokeru_pixel.avd\*.lock"
```

### `flutter pub get`が遅い・失敗する

```powershell
flutter clean
flutter pub get
```

### Gradleビルドが失敗する(namespace関連)

`isar_flutter_libs`等の古いFlutterプラグインはAGP 8.x以降が要求する`namespace`を持たない。
`android/build.gradle.kts`にAndroidManifestの`package`属性から`namespace`を補完するフックを
入れているため、通常は発生しない。発生した場合はそのフックが正しく効いているか確認する。

### `flutter analyze`でエラー

```powershell
dart fix --apply       # 自動修正
dart format .          # フォーマット
```

## 10. バックエンド(kumayokeru-backend)との連携(Phase2以降・仲間との位置共有に必要)

> 出没情報の投稿・仲間との位置共有・ログイン機能に必要。Cognito等のマネージドサービスは使わず、
> 自前バックエンド [nakayu206/kumayokeru-backend](https://github.com/nakayu206/kumayokeru-backend)
> (Node.js/Fastify)を使用する方針([全体設計書.md](全体設計書.md)セクション7参照)。プライベートリポジトリのため、
> アクセス権限がない場合は管理者に確認すること。

### 10-1. 本番APIへの接続(ローカル環境構築不要)

出没情報APIは既にAWS EC2上で稼働中のため、多くの場合ローカルでバックエンドを起動する必要はない。

- ベースURL: `https://57-182-248-130.sslip.io`
- API仕様(Swagger UI): `https://57-182-248-130.sslip.io/documentation`
- 例: `GET https://57-182-248-130.sslip.io/sightings`

### 10-2. バックエンドをローカルで動かしたい場合

```powershell
git clone https://github.com/nakayu206/kumayokeru-backend.git
cd kumayokeru-backend
npm install
npm start
```

`http://localhost:3000` でAPIにアクセスできる。詳細は
[kumayokeru-backend/docs/環境構築手順.md](https://github.com/nakayu206/kumayokeru-backend/blob/main/docs/環境構築手順.md)を参照。

### 10-3. 認証・位置共有APIについて

2026-07-29時点で稼働しているのは出没情報API(`/sightings`)のみ。認証(JWT + bcrypt)・位置共有(POST+ポーリング)・
プッシュ通知(FCM/APNs)はkumayokeru-backend側で実装中([issue #5](https://github.com/nakayu206/kumayokeru-backend/issues/5) /
[#6](https://github.com/nakayu206/kumayokeru-backend/issues/6) /
[#7](https://github.com/nakayu206/kumayokeru-backend/issues/7))。エンドポイント確定後、本ドキュメントを更新する。

### 10-4. 動作確認

```powershell
flutter pub get
flutter analyze
```
